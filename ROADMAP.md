## 2. Направления развития

### 2.1 Из «поисковика по закладкам» в «память агентской фабрики» (P0 — стратегия)

Проект включён в глобальную агентскую фабрику — значит, главный потребитель теперь не
человек, а агенты. Из этого следуют приоритеты:

1. **`kb_ingest` — MCP-инструмент записи.** Сейчас фабрика может только читать.
   Инструмент `kb_ingest(url, category?, note?)` (scrape → embed → upsert через
   тот же kb-api) превратит Misty Garden в накопительный контур: агент наткнулся
   на полезное → сразу положил в базу. Технически: `POST /ingest` в kb_api +
   тонкий MCP-прокси, переиспользует `scrape_articles`/`index_articles` логику.
   Защита от мусора: quality filter уже есть (≥150 символов), плюс whitelist категорий.
2. **`kb_stats` / `kb_health` MCP-инструменты.** Агент перед поиском может проверить,
   что сервис жив и сколько в базе (метаданные помогают рассуждать «спросить ли вообще»).
3. **Контракт ответа для агентов.** Сейчас `kb_search` возвращает chunk_text целиком —
   для Claude это перебор по токенам. Параметр `detail: "snippet" | "full"` (snippet
   = первые 300 символов + score) дёшево и сильно режет контекстные расходы фабрики.
4. **Интеграция с n8n уже заявлена** (в docstring kb_api). Оформить как webhook
   `/ingest` с простым токеном — тогда любые пайплайны фабрики (RSS, дайджесты,
   переписки) смогут сами пополнять базу без MCP.

### 2.2 Качество поиска (P1)

5. **Reranker `bge-reranker-v2-m3`** — топ-20 → rerank → топ-5. Следующий
   предсказуемый буст после title-префикса (есть в BACKLOG, подтверждаю приоритет).
   Модель ~1GB, грузится в тот же kb-api процесс — GPU не обязателен.
6. **Расширить golden set до 15–20 вопросов** и зафиксировать baseline. Без цифр
   «улучшение качества» непроверяемо: любое изменение (reranker, chunking, префиксы)
   гонять через `smoke_test.py` и писать score в историю.
7. **`POST /embed` в kb-api** (кандидат №1 из BACKLOG). Убирает вторую копию модели
   в Windows-venv и становится обязательным precondition для п.1 — иначе ingest
   через агентов будет грузить torch в каждом процессе.

### 2.3 Актуальность данных (P1)

8. **Пересборка устаревших статей.** Статьи обновляются; эмбеддинги — нет. Хранить
   `fetched_at` в payload, раз в N месяцев перескрейпивать старше порога (habr-домены
   с уже настроенными delay). Иначе через год база отвечает устаревшими версиями статей.
9. **Закрыть петлю inbox → каталог → индекс.** Сейчас: ссылки в `inbox.txt`,
   `get_titles_v2.py` разносит по каталогам, `update_kb.ps1` индексирует. Работает,
   но руками. Автоматизация: запланированная задача раз в неделю (cron/WSL Task
   Scheduler) — inbox → каталог → scrape → index → smoke_test → отчёт.

### 2.4 Эксплуатация (P2)

10. **Пины зависимостей + lock** (`pip freeze` в `requirements.lock.txt`) —
    «работало вчера, сегодня нет» уже один раз почти случилось с Qdrant.
11. **Non-root user в Dockerfile** (из BACKLOG) + `start_period: 60s`.
12. **Smoke в CI.** GitHub Actions: поднять compose, прогнать `smoke_test.py`
    на golden set. Ловит регрессии до того, как они доедут до машины.
13. **Бэкап `qdrant_storage/`** — сейчас данные живут только в одном каталоге.
    Еженедельный архив каталога (он маленький, текстовые payload) или
    `qdrant-client` snapshot API.

### 2.5 UX (P3)

14. Webui: история поисков, ссылка «открыть в Qdrant dashboard», показ общего
    числа проиндексированных статей на старте (через `/health`-расширение).
15. Chat: контекст диалога (сейчас каждый вопрос независим) — либо follow-up
    rewrite через тот же LM Studio, либо прямолинейно: последние 2 пары в промпт.

## 3. Что сознательно НЕ предлагаю (и почему)

- **Переименование коллекции `kb` → `misty-garden`** — миграция ради эстетики,
  репутационный риск поломки индекса. Решение зафиксировано в temp_plan.md §4.
- **LlamaIndex** — см. BACKLOG: осознанно не взят, триггер пересмотра — разнородные
  источники (PDF, Confluence, wiki).
- **GPU-эмбеддинги сейчас** — query на CPU ~200 мс, не болит. Делать вместе с
  `POST /embed` при массовой переиндексации.
- **Переезд каталога ссылок в БД** — markdown-каталог и есть источник истины,
  GitHub даёт diff-историю и Ctrl+F бесплатно.

| Итерация | Состав | Результат |
